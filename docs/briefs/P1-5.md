**Ship precondition (D24):** this `nodb` worker exports `GATE_SKIP_LIVE=1`; a risk-high server-data-path task may not ship while the gate reports the live suite skipped. It needs a gate run with live RLS first; never edit the gate.

## Done when
- Each list shows 25 rows per page, stable order, page in the URL, count over the filtered set. Filter or sort change resets that page; a bad page value means 1; a page past the end lands on the last page.
- Supplier spend totals and expense category chips cover the full scope, not the page. Performance rows and workspace timings use the full selected history.
- Cash: three independent pagers; an order with any collection never shows as uncollected.
- A failed read throws to `src/app/(app)/app/error.tsx` (reason + retry), never an empty list. Zero rows keeps the existing empty state.
- Admin guards, session client and RLS unchanged; money and timing definitions unchanged.

## Edge cases
- PostgREST answers an offset past the count with an error (416, `PGRST103`), not an empty page: treat it as out-of-range (fetch the count, redirect to the last page), not as a failure. Same after deleting the last row of a page (`router.refresh`).
- Collections whose `order_id` is null (order deleted) still list in outstanding and deposits.
- `.in()` with hundreds of ids overruns the URL: chunk.
- Date-window history keeps relying on RLS for workspace scope.
- Stale: the cash tab now loads every delivered order and filters in memory; both reads are silently capped today.
- Out of scope, add to `docs/BACKLOG.md`: product and supplier select options, product expenses and supplier detail expense lists, Income tab are still capped.
