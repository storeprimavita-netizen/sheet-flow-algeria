## Definition of done
- Tables `product_options`, `product_option_values`, `product_variants`, `product_variant_values`: workspace_id, RLS (admin write, agents read, no cost fields), `set_updated_at`, `revoke all from anon` (00040 pattern), audit_row() on options/values only. No `uuid[]` column.
- Integrity (review-1 #2): options unique `(id, product_id)`; values unique `(id, product_id, option_id)` with FK `(option_id, product_id)`; variants unique `(id, product_id)`. Join table carries `product_id, option_id`; composite FKs `(variant_id, product_id)` and `(value_id, product_id, option_id)`; unique `(variant_id, option_id)`; trigger refuses a variant whose value set equals another variant's of the same product. `product_id` immutable (trigger) on options, values, variants. All composite to `(product_id, workspace_id)` of `products_id_workspace_uniq`.
- `orders` and `stock_movements` get `variant_id` plus FK `(variant_id, product_id) -> product_variants(id, product_id)` NO ACTION, `CHECK (variant_id is null or product_id is not null)`, index on `variant_id`. Variants are deactivated (`is_active=false`), never deleted once referenced.
- Variant INSERT needs `stock = 0`; stock changes only via a movement (guard like `products_stock_guard`). No `stock >= 0` (D54.3). `products.stock` stays the total; not assigned = total - sum(ALL variants incl. inactive), as a `security_invoker` view `product_variant_stock_v`. `product_stock_stages`, KPIs unchanged.
- Data migration: each valid `{label,sku}` -> option "Variant" (once per product), value, variant (stock 0) only if the product has no value with that label yet; skip blank/non-object/duplicate; re-run adds nothing. `products.variants` kept. Old orders keep text label, `variant_id` null.
- Order stock follows the variant, incl. a variant change (D54.6). `orders.variant` label snapshot written by a BEFORE trigger from `variant_id` (every path stays right). Refuse an inactive variant on order INSERT and on UPDATE of `variant_id`.
