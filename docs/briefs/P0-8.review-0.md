VERDICT: FIX

## Summary
Brief review (qa-reviewer, read-only queries on the local DB inside a rolled-back transaction). The three-stage reconcile is the right shape.
Two high gaps: the swap link was dropped from the target, so a swapped original deducts again (the D31 regression comes back), and the add-only
trigger breaks order and workspace deletes that cascade into stock_movements. Five medium gaps: the view is not admin-only, a legacy reason is
missing, existing orders are never reconciled, B holds nothing before it ships, and swap_order has no status allow-list. Fix the brief, then re-review.

## Findings (ranked)

1. **HIGH: a swapped original deducts again** (brief L11, L24). The target reads only `delivery_status`. Under D36, `apply_zr_state` (00027:63) can move A from `swap` to `delivered`/`returning`, which puts A back at -qty while B also holds -qty. That is two deductions for one piece, the regression D31 fixed.
   **Fix:** target = 0 whenever `swapped_to_order_id is not null`. Add `swapped_to_order_id` to the trigger's watched columns. Leave linked originals out of the view's on road and delivered.
2. **HIGH: add-only trigger blocks cascades; test cleanup cannot work** (L25, L32).
   - `stock_movements.order_id` is `ON DELETE SET NULL` (00004:98). Deleting an order runs an UPDATE on its movement rows, which the trigger refuses.
   - Workspace deletes cascade the same way (`cash.test.ts:46`).
   - `orders.product_id` has no ON DELETE action, so "afterAll deletes the product only" fails.
   **Fix:** allow UPDATE only when the single change is `order_id` set to null and that order is gone. Allow DELETE only when the product or workspace is gone. Test both.
3. **MEDIUM: `product_stock_stages` is not admin-only** (L14, L27). It is security_invoker over `products`, and `p_sel` lets every role read products (00003). Agents would see stage totals.
   **Fix:** add `where public.is_admin()` and revoke from anon. Put the stage sets in one SQL function that both the trigger and the view call.
4. **MEDIUM: legacy reason `order_reverted` is missing from "current"** (L13). There are 3 such rows locally; leaving them out over-restores stock.
   **Fix:** list the reasons exactly: `order_confirmed, order_reverted, order_returned, order_stock_sync, order_swapped, delivered, returned`.
5. **MEDIUM: "no backfill" leaves terminal orders wrong** (L41). Locally, 8 orders differ from the new target, 4 of them cancelled orders still holding stock that will never reconcile.
   **Fix:** a one-time reconcile pass in a separate migration 00029, or a `correction`-reason recount. Not in 00028: a new enum value cannot be used in DML in the same transaction that adds it.
6. **MEDIUM: B holds nothing until it ships** (L15, L26). B is created as `wait_for_deposit` (target 0) while A going to `swap` gives +qty back, so the warehouse counts a piece that is with the carrier, against D34.
   **Fix:** treat a swap replacement in `wait_for_deposit` as on road, reconcile B after the link is set, and leave B out of reserved.
7. **MEDIUM: `swap_order` has no status allow-list** (L26). D31 allows a swap only from returning, returned, exchange or delivered.
   **Fix:** check that list after the lock, check that A has a product, and check that `p_customer_id` is in A's workspace (FK checks bypass RLS).
8. **LOW: relabelling `order_confirmed` as "left for delivery"** mislabels 41 existing rows that were written at confirmation. **Fix:** add a new reason, e.g. `order_shipped`.
9. **LOW: admins can hand-insert `order_*` rows** that then count in an order's "current". **Fix:** the insert policy's WITH CHECK allows only `purchase`/`correction` with `order_id is null`. Revoke UPDATE/DELETE/TRUNCATE from anon, authenticated and service_role (TRUNCATE skips row triggers).
10. **LOW: search path.** Use `search_path = public, pg_temp` (or `''`) on the security definer functions.
