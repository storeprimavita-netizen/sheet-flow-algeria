# MONEY-1 — Three-account ledger

risk: high · surface: security · lane: money

Goal: provision ZR, DZD and USDT balances per workspace, preserve legacy finance, and let an admin record a ZR payout as one atomic transfer.

## Done when

- Each existing and new workspace has exactly one system account of each kind. ZR and DZD use DZD. USDT uses USDT. App callers cannot create, delete, re-key or change the currency of a system account.
- A workspace admin can append dated in/out entries and record a transfer, including ZR → DZD payout and DZD ↔ USDT with the rate used. A transfer writes one debit and one credit under the same transfer ID in one transaction. Replaying the same request cannot move cash twice. Corrections are reversing entries.
- Balances reflect opening amount and movements once, in account currency. The Accounts and Overview balance reads and existing cash-input paths continue working. Profit and KPI formulas stay outside this ledger. MONEY-2 owns screens and MONEY-3 owns the paid-from workflow.
- Existing account records and movements are retained, links are mapped per D39, and historical amounts are never silently relabelled into a different currency. Agents and other workspaces cannot read or write the ledger or invoke money RPCs successfully.

## Files and order

1. Add `USDT` to `currency_code` in the next numbered migration. Use a separate following migration for constraints, seeds and casts that use the new value. Extend the `exchange_rates` currency check with the existing manual rate semantics. Keep general form currency choices unchanged for MONEY-1.
2. Add system accounts in the next migration. Preserve original `accounts` rows in a read-only legacy relation with IDs, currency, balances and audit history intact, and keep a legacy-ID mapping. Recreate the public `accounts` API shape with the existing fields plus immutable kind, using unique (workspace_id, kind), valid kind/currency pairs, admin-only RLS, updated_at and audit. Seed all current workspaces and use a private workspace insert trigger patterned on 00056 for future ones. Scope structural account writes to the migration and seed path, including explicit grants.
3. Repoint `expenses.account_id` and `ad_spend_daily.account_id` to system accounts via workspace-scoped FKs. Map clearly named courier balances to ZR, dinar cash/bank to DZD and named crypto/Binance/USDT to USDT (D39). Keep the original account and movement amounts and links in the migration record. Fold compatible opening balances and import compatible positive topups as dated ledger entries with source references. If a nonzero legacy opening/topup would change currency or an account cannot be mapped under D39, fail atomically with the affected IDs/currencies and raise the actual mapping/rate question. Never infer USD = USDT. The local database has zero legacy accounts and topups, so test a pre-migration fixture as well.
4. `account_entries`: workspace FK, composite account FK, occurred_on, direction, finite positive numeric amount at documented precision, category (existing workspace option-set model for money_category), note, created_by, timestamps with the standard updated_at trigger, transfer ID/rate and optional workspace-scoped expense/ad-spend/contact links. Leave courier payment link for ZR-4 if its source table does not exist. Use admin SELECT RLS, insertion through guarded functions, one insert audit trigger and no app mutation privileges on existing entries. Keep test-only service cleanup compatible with the audited table list. Index workspace/account/date and enforce unique debit/credit legs by transfer ID.
5. Use fixed-search-path admin/workspace-checked functions for append and transfer (including a typed ZR payout entry point or the same constrained transfer API). Pass a stable request key for retryable transfers and reject changed input for an existing key. Stamp the actor from auth.uid(). Require same-account-currency parity for ZR → DZD and retain a positive DZD-per-USDT rate and both amounts for DZD ↔ USDT. Revoke default/public/anon function grants. Never expose arbitrary transfer legs to independent writes.
6. Replace `account_balances` in place, retaining existing columns, invoker security and no anon privileges. Add ledger movements. Keep linked expense/ad-spend rows contributing until MONEY-3 moves those writes into the ledger. Count each source only once when it has a linked entry. Use the row's amount when its currency matches and stored amount_dzd for legacy foreign expense/ad-spend debits on a DZD account. Fail migration on a linked debit whose value in its mapped account currency cannot be proved. Preserve legacy topup rows for audit and count their imports only through the ledger.
7. Keep this stage backend-only. In `src/app/(app)/app/money/accounts/actions.ts`, point the existing topup action at the append RPC and keep current revalidation and role check. Limit the existing edit action to permitted non-ledger settings and prevent opening balance rewrites, and the old create action reports the system-account restriction. Do not redesign the screen. Add `account_entries` and any newly audited relation to the shared audited tables, test cleanup and EN/AR audit labels. Update `docs/DB.md` with RPC/RLS, rollover checks, rates and balance compatibility. Run local reset, generate types with `scripts/gen-types.sh`, then run the full live gate.
