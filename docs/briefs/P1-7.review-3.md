## Findings (ranked)

1. **MEDIUM — the grid switches still reset after a failed save (review-2 #1, open).** `src/app/(app)/app/settings/fees-section.tsx:90-140` (Switches at :103, :122, :140)
   - Cause: React 19 calls `form.reset()` after every form action, even one that returns `{error}`. Radix Switch 1.3.7 listens for `reset` and calls `setChecked(initialChecked)` (`node_modules/@radix-ui/react-switch/dist/index.mjs:92`). On a controlled switch, that call goes through `onCheckedChange`, so making `stop`/`priced`/`desk` controlled changes nothing.
   - Failure: turn stop-shipping on for Adrar and turn Priced on for Chlef with no fee, then Save. The error `errNeedFee` appears and both switches go back to off. The stop flag is lost without any sign, and a later successful save keeps it off. The typed fee text survives.
   - Same cause in the order form: Radix Select also listens for `reset`.
     - A `createOrder` error resets the delivery type to home, which re-seeds the fee and wipes a manual fee override (`orders/order-form.tsx:177`).
     - The same error clears the size (`:109`).
     - The swap-card fields are still uncontrolled.
     - Name, phone, address, price and quantity now survive an error.
   - Fix: in all three forms, submit with `onSubmit={e => { e.preventDefault(); startTransition(() => formAction(new FormData(e.currentTarget))); }}` so React never resets the form. Another option is to return the submitted values in the action state and re-seed from them.
2. **MEDIUM — the CSV accepts a priced `:0` fee without warning (review-2 #7, now medium).** `src/lib/delivery-prices.ts` (parser) and `settings/actions.ts:343-349`
   - Failure: the line `DZ,2-Chlef,,,rate,,<home label>:0` previews as "No price → 0 DA" with 0 warnings. Apply then stores `priced=true, home_fee=0`. The grid shows Priced on with an empty fee box, and orders to Chlef are charged 0 DZD delivery.
   - Clearing the fee on a row that is already priced also saves 0, because the zero guard only runs when a wilaya is being switched on.
   - A remote row with `priced`, `stopdesk_available`, `home_fee>0` and `stopdesk_fee=0` still charges 0 DZD for stop-desk, because 00054 only backfills rows where both fees are 0.
   - Fix:
     - Parser: warn on any fee ≤ 0 and treat that type as unavailable.
     - `apply_delivery_prices` and `saveWilayaFees`: reject a priced fee ≤ 0 on every save.
     - Backfill `stopdesk_available=false where stopdesk_fee=0 and home_fee>0`.
     - Grid: flag any priced row with a 0 fee.
3. **LOW, needs an owner decision — ZR sync can no longer make a wilaya shippable.** `settings/actions.ts:266-276`
   - Sync writes fees only, as the brief requires. Since 00054 every unpriced row stays "No price", but the admin still sees "58 updated".
   - Options for the owner:
     - (a) Keep the brief's precedence and say clearly in the sync result that the fees were saved but the wilayas stay unpriced.
     - (b) Set `priced=true` when ZR returns a fee above 0. This contradicts the brief's rule "ZR sync never touches `priced`".
4. **LOW — `/app/orders/new` returns a 500 when no product is chosen.** `src/app/(app)/app/orders/actions.ts:395`. `createOrderSchema.parse` throws on `product_id`, the error boundary replaces the form, and everything typed is lost. Fix: use `safeParse` and return `{error}`, and require a product in the form.
5. **LOW — a webhook payload fee of 0 passes the push exception (review-2 #5, open and wider than reported).** `src/lib/webhook.ts:221` and `src/lib/integrations/zrexpress-push.ts:61`. When Shopify or WooCommerce sends `shipping_fee: 0` for a stop-desk order to a home-only wilaya, the fee is not null, so the order is pushed with COD = sale only. Fix: treat a payload fee of 0 as no fee, or base the exception on `delivery_fee_source` and `created_at` versus `wilaya_fees.updated_at`.
6. **LOW — `switchOrderToHome` still has no state guards and returns raw English errors (review-2 #6, open).** `orders/actions.ts:129`.
