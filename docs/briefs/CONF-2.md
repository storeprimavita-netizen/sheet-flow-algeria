# CONF-2 — Saved-view Kanban

risk: high · surface: ui,security · lane: orders

Goal — Display scoped order views as boards and let permitted users move cards through the existing status workflow by drag or by keyboard.

## Done when

- Confirmation, Shipping and All resolve table or board from the active saved view and a URL layout override. Save and Save as mine preserve layout, grouping and card fields under existing shared/personal rules. Old rows default to table and old Shipping `?view=kanban` links still work.
- Confirmation ships with a shared Kanban by status view. Default grouping is confirmation status in Confirmation and All, delivery status in Shipping. Attempts, wilaya and product are display groupings. Their cards still have the same status control. Card fields are selectable from available product, wilaya, total, attempts, age and score fields within each scope and role. Use existing amount meanings, risk badges and DTOs.
- A permitted drop and the on-card keyboard/touch status select use one transition path. Confirm consequential statuses using existing status metadata and a project dialog. Rejected moves leave the card and its prior state visible with a translated reason and retry. Preserve the saved confirmation note. Confirmed cards leave the Confirmation queue after refresh. Shipping stays read-only for non-admins, and `swap` stays display-only. Status labels and swap links remain visible.
- Lists keep existing RLS-scoped queries, page bounds, show-closed and search semantics. Boards offer the relevant existing order detail/calling path, no-match reset, empty and error states, and pending feedback without horizontal page overflow. Non-status group headings and missing values remain legible in RTL.
