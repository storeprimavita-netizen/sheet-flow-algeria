## Findings

1. **MEDIUM**: `supabase/migrations/00030_stock_followup.sql:17`. `order_stock_target` returns 0 for any replacement with `confirmation_status='cancelled'`, whatever its delivery stage.
   - Reproduced: swap (stock -1), replacement goes `in_transit` (-1), then an admin sets confirmation `cancelled` through bulkTransition or the RPC.
   - Result: stock goes back to 0 and the log writes `order_returned +1` while the parcel is still with the carrier.
   - After ZR syncs `delivered`, stock stays 0, so a delivered piece is counted on the shelf for good.
   - A non-replacement order in the same state keeps its -qty, so the two cases disagree. This breaks D34 ("delivered is gone") and D40 (never show stock that is not on the shelf). D43 covers only a replacement still waiting for deposit.
   - Fix: `when p_confirmation = 'cancelled' and p_replacement and p_status = 'wait_for_deposit' then 0`. Equivalently, add `and p_confirmation is distinct from 'cancelled'` to the wait_for_deposit replacement branch and drop the first branch.

2. **LOW**: `00030_stock_followup.sql:297`, `src/lib/statuses.ts:254`. The order detail select still offers every status when the current status is `swap`.
   - If an admin moves original A out of `swap`, it can never return: the guard refuses `swap`, and `swap_order` exits early because A is already linked.
   - Stock is fine (a linked order targets 0), but A's status and KPIs stay wrong.
   - Fix: when the current status is `swap`, show it read-only with no other options, or refuse in the DB any delivery_status change on a linked original.

3. **LOW** (review-1 #6, still open): `00030_stock_followup.sql:391` with `src/app/app/products/actions.ts:203-205`.
   - The policy accepts `created_by is null`, the app never sends `created_by`, and the column has no default. Every manual purchase or correction line is therefore unattributed.
   - Fix: give the column a default of `auth.uid()`, or add a BEFORE INSERT trigger that forces `new.created_by := auth.uid()` when a session exists. Then drop the null branch.
