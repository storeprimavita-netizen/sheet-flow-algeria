# P0-8 `order_stock_effects`: undo stock when an order leaves `returned`
risk: high · surface: none · lane: orders   (migration + stock trigger; live RLS suite required, D24)

## Goal / done when
- Order `delivery_status` moves OUT of `returned` => one `stock_movements` row (+delta = -quantity, reason `order_return_undone`), so products.stock nets to the same as if the return never happened.
- Net-based guard: undo only if the order has more `order_returned` than `order_return_undone` rows (idempotent, no negative drift on odd histories).
- returned -> X -> returned -> X yields stock net 0; returned only once yields +qty; existing branches (confirm / return / revert) unchanged.
- Gate green incl. rls/sync tests; types regenerated; DB.md + i18n updated.

## Confirmed in code
- Latest `order_stock_effects` is 00018 (AFTER UPDATE trigger `orders_stock_effects`, security definer). Branches: (1) confirm => -qty `order_confirmed`; (2) `delivery_status` -> returned => +qty `order_returned`; (3) confirmed fall-back before delivery => +qty `order_reverted` (guard excludes delivered/returned/exchange/swap).
- Nothing handles leaving `returned`: ZR `apply_zr_state` (00027 L63) or an admin correction (returned -> delivered / in_transit) leaves the restocked units counted although the parcel is out again. Overstates stock.
- `stock_movements.delta <> 0` check; `apply_stock_movement` trigger updates products.stock. Enum `stock_reason` base: purchase, correction, delivered, returned + 00018 order_*.
- Tests: `src/lib/integrations/zrexpress-sync.test.ts` counts rows with reason `order_returned` only (L53), so adding a new reason does not break them (L112 expects 2, L123 expects 1: keep).
