## Goal / done when
- Stock is reconciled to the parcel stage; products.stock = pieces in the warehouse; add-only log; swapped holds nothing once.
- Target (SQL fn `order_stock_target(status, qty, is_linked_original, is_replacement)`; the ONLY place; trigger and view both call it):
  0 if `swapped_to_order_id is not null` (D31, whatever the status); else `-qty` if status in (bureau_deposited, in_transit, out_for_delivery,
  stop_desk_waiting, delayed, returning, exchange, delivered), or if status = wait_for_deposit AND the order is a swap replacement
  (some order has `swapped_to_order_id = this.id`; decided: B is physically with the carrier, D34); else 0 (wait_for_deposit, returned, cancelled, swap).
- current = sum(delta) of this order+product rows with reasons exactly `order_confirmed, order_reverted, order_returned, order_stock_sync, order_swapped, order_shipped, delivered, returned`;
  insert one movement `target - current`. Reasons for new rows: leaving to carrier `order_shipped` (new; `order_confirmed` keeps its old label on 41 legacy rows), back `order_returned`, swap link `order_swapped`, anything else `order_stock_sync`.
- Trigger fires AFTER INSERT OR UPDATE OF delivery_status, quantity, product_id, swapped_to_order_id; skip when none changed. Insert already on road deducts at insert; `product_id` set null while on road releases the stock; product change releases old product first (reconcile per order+product).
- View `product_stock_stages` (security_invoker, `where public.is_admin()`, revoke from anon): in stock = products.stock; reserved = qty confirmed + wait_for_deposit, not replacement, not linked original, not cancelled; on road = qty of the on-road set excl. delivered and excl. linked originals; delivered = qty delivered excl. linked originals.
- Add-only (D35): policies select + insert only (admin, workspace; insert WITH CHECK reason in `purchase`,`correction` and `order_id is null`). `revoke update, delete, truncate` on stock_movements from anon, authenticated, service_role.
  Trigger `before update or delete` raises `stock log is add-only` EXCEPT: UPDATE where only `order_id` changes to null and the old order no longer exists (FK set null); DELETE where the product row or the workspace row is gone (cascade). Verify the cascade visibility at build; the FK actions run as table owner so revoke does not block them.
- `swap_order` (security invoker, `search_path = public, pg_temp`): `is_admin()` else raise; lock A `for update`; A.product_id not null; A.status in (returning, returned, exchange, delivered) else raise; `p_customer_id` must belong to A's workspace; if A.swapped_to_order_id set return it (double submit); insert B; A -> `swap`; link; then reconcile B explicitly (after link). Deleting B unlinks A (FK) and A reconciles by its status.
- All security definer functions: `search_path = public, pg_temp`.
- Gate green, live RLS suite 3x, types regen `--local`, DB.md, i18n key parity.
