## Findings (ranked)

1. **MEDIUM** `src/app/app/orders/all/orders-all-table.tsx:122,146`. The order-number column is `max-w-[9rem]`, so the badge truncates to "Swapped to or…". The replacement number, the whole point of the badge, is only visible in the `title` tooltip (list-en-dark.png). Fix: let the badge wrap, or render a short form (icon + "#B") with the full sentence kept as `title`/aria-label, or widen the cell. Check AR as well.
2. **MEDIUM** `src/components/swap-badge.tsx:12-16` with `src/messages/ar.json:394`. In AR the Latin order number is not isolated and renders as "e2c9fddb#" (kanban-ar-light.png, detail-ar-light.png). Fix: render the number inside `<bdi>` (next-intl `t.rich` with a `num` tag, or a `dir="ltr"` `<bdi>` around `#{number}`).
3. **LOW** `src/app/app/orders/delivery/delivery-table.tsx:75-78`. At 1280px the badge sits inline next to the `whitespace-nowrap` number, which pushes the status column past the viewport so the status select is clipped on every row (kanban-en-dark-2.png, which is the table). Fix: stack the badge under the number, as the list does.
4. **LOW** `src/app/app/orders/swap-order.test.ts`. The "double submit" test makes one call: it asserts `.is("customer_id", null)` but never submits twice. "non-uuid" asserts a bare `rejects.toThrow()`, so any error passes. Fix: call twice with a mock that matches 0 rows the second time and assert no overwrite; assert the error message.
5. **LOW** `src/lib/settings.test.ts`. Only the map-with-`swap` case is covered. Add: a map without `swap` stays unchanged, an invalid enum value is still rejected, and a non-object map is still rejected. The preprocess in `settings.ts:26-35` itself is correct.
6. **LOW (info)** `src/app/app/orders/[id]/page.tsx:~88`. The forward-link query moved out of the admin block; orders RLS allows agents to read it. The detail page now shows both the badge and SwapCard, which is redundant but harmless.
