## Findings (ranked)

1. **Medium: colon-less home part promotes the stop-desk price.** `src/lib/delivery-prices.ts:129-132`
   - Cause: the `i < 0` branch hits `continue` before `homeSeen = true`.
   - Failure: `توصيل للمنزل 1350|توصيل للمنزل:720` (colon typo) parses to `home: 720, stopdesk: null, priced: true` with only a `malformed_row` warning. The wilaya charges 720 for home delivery and offers no stop desk. This is the same class of bug the brief closes ("second home label stays repeated, not promoted"; D62/D27).
   - The new test `colon-less part warns` (`delivery-prices.test.ts`) asserts `home: 720`, so it locks in the bad outcome.
   - Fix: in the colon-less branch, if `labelKind(part)` (or the label before the trailing number) is `home`, set `homeSeen = true` before `continue`. Change the test to expect `home: null`, the 720 treated as a repeated stop-desk price, and `priced: false`.

2. **Medium: wrong reason when the stopped-wilaya lookup fails.** `src/app/(app)/app/orders/actions.ts:539-546` (`swapOrder`)
   - Cause: the error of the second `wilaya_fees` read is ignored. If it fails, `wf` is null and the user sees `form.blocked.type_unavailable` for a stopped wilaya, which is the misreport this task set out to fix.
   - The same path also returns `type_unavailable` for an unpriced destination, but `orders.form.blocked.unpriced` exists.
   - Fix: check the read's error and return `swap.failed`. Select the full fee row and reuse `newOrderBlock()` from `src/lib/pricing-delivery.ts`, so the reason logic stays in one place.

3. **Medium: swap card lost client-side required checks, and the error text points at the wrong field.** `src/app/(app)/app/orders/[id]/swap-card.tsx:73-81`
   - Cause: the old phone and wilaya inputs had `required`. `PhoneField` and `WilayaCombobox` now have none.
   - Failure: an empty phone or an empty wilaya submits and comes back as `swap.invalid`, whose text says "Check the wilaya code", even when the phone is the problem. There is no field-level cue.
   - Fix: pass `required` through `PhoneField` and mark the combobox as required (hidden input `required` or a client check plus `aria-required`). Make the `swap.invalid` text generic in both en and ar.

4. **Medium: hardcoded English placeholder on the Arabic swap card.** `swap-card.tsx:76-80` together with `src/components/fields/comboboxes.tsx:14`
   - Cause: `WilayaCombobox` defaults `placeholder = "Wilaya"`, and the swap card passes none.
   - Failure: the Arabic UI shows an untranslated "Wilaya", which breaks the rule that every visible string goes through `src/messages`.
   - Fix: pass `placeholder={t("wilaya")}` or a dedicated key.

5. **Low: the new switch guards are check-then-act.** `orders/actions.ts:139-158`
   - Cause: the update is not conditioned on `delivery_status` or `delivery_type`. A ZR push that runs at the same time can land between the check and the update.
   - Fix: add `.eq("delivery_status","wait_for_deposit").neq("delivery_type","home")` to the update and map 0 rows updated to `switch.status`.

6. **Low: no upper bound on fees.** `delivery-prices.ts:~151`
   - `1e23` in digit form passes the regex. Apply then fails with a numeric(12,2) overflow, and a fee like 9,999,999 DZD passes silently.
   - Fix: add a sanity cap and a `malformed_row` warning.

7. **Low: `aria-label` hides the selected value.** Product/Wilaya comboboxes in `order-form.tsx:114,156` and `swap-card.tsx:79`
   - The label replaces the trigger text, so a screen reader announces "Wilaya" without the chosen value.
   - Fix: use `aria-labelledby` pointing to the label and the trigger.

8. **Low: the order-form `invalid` error does not clear.** `order-form.tsx:176-245`
   - That error is caused by name, phone, quantity or price, but `clearError` is only wired to product, size, wilaya, type and fee.

9. **Low: `MoneyField` blur restores "0" for any text.** `src/components/fields/money-field.tsx` onBlur
   - Typing "abc" now blurs to "0", and this affects every `MoneyField` in the app. Restore 0 only when the typed text parses to 0.

10. **Low: the mixed-change toast ignores communes.** `fees-csv-dialog.tsx:~72-92`
