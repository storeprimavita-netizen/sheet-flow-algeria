# P1-1 KPI contract (brief, rev 1 after review-0 FIX)
risk: high · surface: none · lane: stats  (migration 00031, money, admin-only RPC; qa-reviewer + live RLS suite)

**Goal:** one SQL source `kpi_lines` for every rate and money line the dashboard needs (D4, D34, D45, D46); pages and `pricing.ts` only format.

**Done when**
- `orders.excluded_reason` exists (admin-set, null = eligible; check duplicate|test|fake|other).
- One order set per call: `kpi_order_set(from, to, product)` (SQL helper, security invoker) selects the orders; `kpi_lines`, `dashboard_stats`, `pnl_summary`, `pnl_by_product` all consume it, so rates and money share ids (fixes review high 3; net-parity test `rls.test.ts:182` still passes).
- Set rules: in range by ONE predicate `(placed_at at time zone 'Africa/Algiers')::date between from and to`, used by every function touched (also replaces `placed_at::date` in pnl_lines/pnl_summary/dashboard_stats). Out = `excluded_reason is not null`, or `is_duplicate_suspect` while still unconfirmed (a confirmed/delivered suspect stays in), or a swap original (`swapped_to_order_id is not null`, never by status).
- `kpi_lines(order_ids, from, to, product, filtered)` (internal, order_ids optional) and `kpi_summary(from, to, product)` wrapper (selects its own orders; what finance/product pages call). Both return `{num, den, value, matured}` for confirmation, delivery, return, plus counts received, confirmed, on_road (orders and units), delivered, returned, in_flight. `value` = fraction 0..1 (UI formats percent).
- Money (admin only; agents get rates and no money keys, `usd_rate` null): ad_spend_dzd, `usd_rate` + `usd_rate_date` (latest USD row dated <= least(`to`, today), via `current_fx_rate` logic), ad_spend_usd = dzd / rate, cost_per_delivered and cpa_delivered in DZD and USD (null when no delivered, no rate, or non-product filter), roas, net_profit, waterfall parts that sum exactly to net_profit (revenue, cogs, returns, ads, expenses+fixed; delivery fee is pass-through, no part).
- Every view replaced in 00031 (`product_stats`, `wilaya_stats`, any other) is re-created `with (security_invoker = true)` and keeps its grants and output keys (review high 1). Anon cannot execute `kpi_lines`/`kpi_summary`/`kpi_order_set` (revoke from public, anon; grant authenticated) and has no write on `product_stock_v`.
- `product_stock_v` (security_invoker, admin-only like `product_stock_stages` 00030): product_id, in_stock, reserved, on_road, delivered, sellable (in_stock - reserved, floor 0), low (sellable <= low_stock_threshold).

**Definitions (decided per D40, recorded in D46)**
- Confirmation = confirmed / decided; decided = confirmed + cancelled + no_answer + closed_phone (all four are an answer attempt that ended the funnel; wait_for_confirmation is undecided). `of_received` secondary. Swap replacements are NOT in received/confirmation (born confirmed), but ARE in delivery/on_road.
- Delivery = delivered / (delivered + returned + cancelled-after-pickup); cancelled-after-pickup = delivery `cancelled` AND a `zr_shipments` row exists (or a carrier-status history entry); delivery-cancelled with no shipment stays out. in_flight shown beside.
- on_road (review 4) = `order_stock_target(...) < 0 and delivery_status <> 'delivered'`, ignoring eligibility and dates, units and order counts. Parity test with `product_stock_stages.on_road` runs on units, null dates, no eligibility. Stage lists elsewhere (`stage_counts.shipped`) are replaced by this.
- matured, relative to now(), per metric: den >= 10 AND (orders of that metric's cohort still unresolved and placed > 7 days ago) / den <= 20%. Constants in the function, noted in DB.md.
- Money by D45: latest USD rate, not per-row `fx_rate`; DZD stays stored truth.

**Tests**
kpi: rates ignore excluded and unconfirmed duplicates; confirmed duplicate suspect still counted (rates and money same ids); linked original later delivered not double-counted; replacement excluded from confirmation, in delivery; delivery-cancelled with no shipment stays out of denominator; order at 23:30 UTC lands on its Algiers day on every screen; on_road parity (units); ad spend usd = dzd / latest usd rate, null when no rate; cost per delivered null when filtered by wilaya; waterfall sums to net_profit; agent gets rates, no money keys, null usd_rate; product_stock_v agent sees no rows; views keep `security_invoker` (pg_class reloptions) and anon reads return 0 rows; anon cannot execute kpi_lines; other-workspace order ids return 0; `dashboard_stats rates equal kpi_lines`; existing net-parity test passes; pricing.test updates.

**Edge cases / assumptions**
- Local data: 14 originals delivered, 3 suspects (2 confirmed), 52 delivery-cancelled with no shipment, 12 unconfirmed on-road: tests seed their own rows, don't depend on counts.
- Ad spend has no campaign link; product is the finest grain. Collected/paid-out stages are null here (ZR-4, MONEY-1).
- Remote `db push` stays owner-only. New row D46 records the definitions above (decided by Claude, owner may overturn).
