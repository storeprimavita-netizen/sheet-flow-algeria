Goal: an admin imports `Algeria_numbered.csv`-format files (preview, then apply), edits fees per wilaya, and availability + communes follow the data everywhere a fee is read.

## Definition of done
- Pure parser `src/lib/delivery-prices.ts` (+ tests): BOM/CRLF/quoted fields; labels matched by full text after trim+NFC (`توصيل للمنزل` = home, `توصيل للمكتب` = stop-desk; fallback substring `منزل`/`مكتب`); repeated label (Béchar 1350|720) = second is stop-desk + typed warning; commune names normalized (trim, collapse spaces, case-fold key) and deduped with warning; no I/O.
- Availability model (no nullable fees, no 0 DZD): `wilaya_fees` gets `priced boolean not null default true` and `stopdesk_available boolean not null default true`. Unpriced (`extra`) = `priced=false`; home-only = `stopdesk_available=false`. Apply NEVER changes `stop_shipping` (owner's manual flag); preview shows a warning when a wilaya is unpriced and `stop_shipping` is false. Unpriced means shipping off via `priced`.
- One fee source: SQL `delivery_fee_for(ws, wilaya, type)` returns null when unavailable + TS `src/lib/pricing-delivery.ts` `deliveryFeeFor(row, type)`. Used by: `src/lib/webhook.ts:225-232` (no fee seeded when null), `orders/new/page.tsx:21`, `swap_order` RPC (00044:254; new migration redefines it, refuses unavailable type), `syncZRFees` (`settings/actions.ts:~242`), push guard. Precedence: CSV apply and ZR sync both write fees only; ZR sync never touches `priced`/`stopdesk_available`; last write wins.
- Push guard (new orders only): refuse when type unavailable; existing stop-desk orders to a now home-only wilaya keep their fee and push still works (warning logged, admin may override). Guard reads filter `.eq("workspace_id", workspaceId)` (service-role path `orders/actions.ts:74`).
- `saveWilayaFees` reads+writes both flags; "no price" never becomes 0; refetch after apply; compare `updated_at` to avoid overwriting a concurrent apply.
- Gate green, EN/AR parity, no hardcoded colors, live RLS suite passes.
