# CONF-3 — Customer score card

risk: high · surface: ui,security · lane: orders

Goal — Open a customer's visible history from the Confirmation customer name without slowing queue rendering or leaving the order.

## Done when

- Confirmation table and Kanban customer names open one card. Mouse users can hover and move into it. Keyboard users can use Enter or Space, and phone users can tap. Escape dismisses it and restores keyboard focus. The existing row sheet, call controls, drill-in and board drag/status controls still work. Shipping and All keep their existing customer-name behavior.
- The card shows scope, total, delivered, returned, cancelled and no-answer counts, score band with a count-based reason, matured SQL delivery rate, last order date and status, orders of this product and other open orders with the same normalized phone. The linked customer detail opens through View all. Use `OrderNo`, `StatusPill` and existing formatting. Include lifetime delivered value only for admins. Keep phone, address, costs, margins, payout values and unrelated order totals out of the card response.
- Workspace history applies to admins and visible history to agents, as in D98. Label both the score and delivery history as based on visible orders for agents. Show “No visible orders” for an empty linked agent history. Distinguish unlinked, new, unscored and numeric zero. An unresolved customer link gets its own translated state, no aggregate score, and any separately matched visible open orders. Preserve an adverse reason even if the score rounds to zero, show insufficient history for an immature delivery cohort, and omit missing product and last-status details.
- Load one scoped snapshot on first open, with loading, empty, error and retry states. Reopening the same trigger briefly reuses its successful snapshot only for the same user, workspace, role and order. Fetch on open and keep the delivery cohort out of queue rendering.
