# CONF-3 — Customer score card

risk: high · surface: ui,security · lane: orders

Goal — Open a customer's visible history from the Confirmation customer name without slowing queue rendering or leaving the order.

## Done when

- Confirmation table and Kanban customer names open one card. Mouse users can hover and move into it. Keyboard users can use Enter or Space, and phone users can tap. Escape dismisses it and restores keyboard focus. The existing row sheet, call controls, drill-in and board drag/status controls still work. Shipping and All keep their existing customer-name behavior.
- The card shows scope, total, delivered, returned, cancelled and no-answer counts, score band with a count-based reason, matured SQL delivery rate, last order date and status, orders of this product and other open orders with the same normalized phone. The linked customer detail opens through View all. Use `OrderNo`, `StatusPill` and existing formatting. Include lifetime delivered value only for admins. Keep phone, address, costs, margins, payout values and unrelated order totals out of the card response.
- Workspace history applies to admins and visible history to agents, as in D98. Show “No visible orders” for an empty agent history, and distinguish new and unscored from numeric zero. Preserve an adverse reason even if the score rounds to zero. Show insufficient history for an immature delivery cohort and omit a missing product or last status rather than fabricating one.
- Load one scoped snapshot on first open, with loading, empty, error and retry states. Reopening the same trigger briefly reuses its successful snapshot. No eager delivery cohort query, shared authenticated cache, delayed-result bleed between orders, or request on row render.

## Steps and files

1. `supabase/migrations/00089_confirmation_customer_score.sql` — add one stable read-only `security invoker` RPC, `confirmation_customer_score(p_order_id uuid)`, with fixed empty search path and qualified objects. Revoke default EXECUTE from PUBLIC, anon and service_role, then grant authenticated. Require an active admin or confirmation agent and the caller's workspace. Anchor on an order visible through existing `orders` RLS with explicit workspace scope. A missing, hidden or other-workspace anchor returns the same empty result. The only client input is anchor order ID.
   - Resolve the customer by visible linked ID in the same workspace, falling back to a matching canonical customer phone for unlinked orders. Match other open orders by exact `normalize_dz_phone` equality to the anchor phone, including legacy raw order numbers without a customer ID. Reject blank matches. Add an expression index on workspace and normalization of `orders.customer_phone`. Filter known actionable Confirmation states or confirmed with actionable Delivery states using the same state sets as `src/lib/statuses.ts`. Exclude the anchor. Return up to five matches ordered by `placed_at` then ID with an indication if more exist. Return only ID, order sequence, dates and status keys. Check the indexed phone predicate with a representative local query plan.
   - Join keyed `customer_stats`, `customer_product_stats` and `customer_delivery_stats`. Return only display fields. Gate `lifetime_delivered_value_dzd` with the live admin check. Aggregate counts stay on STATS-1 rather than recalculating from phone matches. Keep existing policies and role permissions. Update `docs/DB.md`, reset locally and regenerate types using approved scripts. Run the fast gate and push the database step.
2. `sell/confirmation/score-actions.ts` and `sell/confirmation/_lib/customer-score.ts` — validate the order UUID with Zod and recheck active admin/confirmation role through `getProfile`. Read once using the session client and the RPC. Map an explicit typed DTO with a safe empty/error result, and omit the lifetime value property for agents. Define typed summary and detail shapes and translation keys for existing STATS-1 states and reasons. Never use a service client.
3. `sell/confirmation/customer-score-card.tsx` — use the existing Radix Popover and a labeled focusable name button. Keep hover open over the panel, and allow click or keyboard activation to hold it open while using links and retry. Do not auto-steal focus on hover. Stop trigger and panel events that would also open the row sheet. Add localized state, count, reason and action strings in `src/messages/{en,ar}.json`. Use logical layout, tokens and viewport-aware popover sizing.
4. `sell/confirmation/page.tsx`, `confirmation-table.tsx` and `confirmation-sheet.tsx` — keep the batch query for lightweight risk summaries with explicit `customer_stats` columns. Present state, reason and visible count where the queue shows a score. Move the old derived delivery-rate cue to the lazy card, which uses the matured SQL metric. Keep existing prior-order, dial and status workflows in the sheet. Wire the table name trigger and Confirmation-only slot in `sell/orders/order-kanban.tsx` with the optional scoped summary in `_lib/kanban.ts`. Preserve the configured Kanban score field and existing output in other scopes. Run fast gate and push the UI step.
