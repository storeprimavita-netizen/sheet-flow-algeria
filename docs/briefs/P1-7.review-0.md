## Summary
Brief review by qa-reviewer and ui-reviewer, with spot-checks of the CSV and code. The direction is sound, but the brief has three blocking problems:
- the Arabic label match can never succeed;
- "never a 0 DZD fee" is broken by fee consumers the brief does not touch;
- applying the CSV would silently undo the owner's manual `stop_shipping`.
Migration: name it 00052 explicitly. There is no object conflict with STORE-3's 00051. Merge STORE-3 first, or flag the out-of-order push to the owner.

## Findings (ranked)

1. **HIGH: brief:22. The label match never fires.** The CSV has `توصيل للمنزل` 55 times and `توصيل للمكتب` 51 times. The substring `المنزل` occurs 0 times (confirmed with grep: `للمنزل` has no alif). Every rate would fall to the positional fallback. The 3 office-first wilayas would get home and stop-desk swapped, so the wrong COD would be pushed to ZR.
   - Fix: match the full labels after trim and NFC (or match `منزل` / `مكتب`).
   - Add a fixture row that lists office first.

2. **HIGH: brief:9 vs `settings/actions.ts:279`, `settings/fees-section.tsx`. The grid save turns "no price" back into 0.** `feeAmount = z.coerce.number().min(0).catch(0)`, and `saveWilayaFees` re-upserts every row. Saving the grid after an import writes 0 DZD for wilayas with no price, and a stop-desk fee of 0 for home-only wilayas.
   - Fix: store "no price" as NULL fees (nullable columns) or derive it from the flags.
   - `saveWilayaFees` must read and write `stopdesk_available`.
   - The grid shows "No price" and disables the fee inputs when the type is unavailable.

3. **MEDIUM: brief:9,21. CSV apply clobbers the manual `stop_shipping`.** `stop_shipping` is the owner's manual stop flag. It is separate from `stop_shipping_auto` and feeds the dashboard RPCs (00031:470, 00031:630). "Replaces fees" would set it to false for every priced wilaya.
   - Fix: apply may only set it to true when a wilaya has no price, or add a separate `priced` / availability column.
   - The preview lists every flag flip.

4. **MEDIUM: brief:25 file list. Fee consumers are missing.** None of these respect the new flags:
   - `src/lib/webhook.ts:227-232` (store and webhook orders) seeds `home_fee` / `stopdesk_fee` without checking them;
   - `orders/new/page.tsx:21` does not pass availability or `stop_shipping`;
   - the `swap_order` RPC (00044:254) copies the fee and delivery type into the new wilaya;
   - `syncZRFees` (`settings/actions.ts:~242`) upserts fees and can re-enable a stop-desk.

   Fix:
   - Add one helper (a SQL `delivery_fee_for(ws, wilaya, type)` and/or a `src/lib/pricing*.ts` function) that returns "unavailable" instead of a fee, used by all of these consumers.
   - Define the precedence between ZR sync and the CSV.

5. **MEDIUM: brief:11 vs brief:40. The push guard contradicts the edge case.** Existing stop-desk orders "keep their stored fee" (line 40), but push then refuses them (line 11). On auto-push this only returns a warning, so those orders are stranded.
   - Fix: pick one rule. For example, refuse only new orders, or warn and allow an admin override.

6. **MEDIUM: brief:25. The guard runs under the service role.** Auto-push calls `pushToZR` with the admin client (`orders/actions.ts:74`). Any `wilaya_fees` or `wilaya_communes` read added to the guard must filter on `.eq("workspace_id", workspaceId)`.

7. **MEDIUM: brief:21. `apply_delivery_prices` hardening and the commune primary key.**
   - The parser must normalize and dedupe commune names (case and whitespace), with a warning. Otherwise a future file aborts the whole apply on a primary-key violation.
   - The function must validate the jsonb: code 1–58, fee ≥ 0 or null, name length, row caps, and no client workspace (use `current_workspace_id()` only).
   - It must `set search_path` and grant execute to `authenticated` only.
   - Resolve the self-contradiction about `updated_at` on wilaya_communes and pick one option.
   - Verified: `wilaya_fees` already has the `set_updated_at` and audit triggers.

8. **MEDIUM: brief:27 (UI). The preview dialog and order form are under-specified.**
   - Preview dialog: a Radix Dialog with a scrolling body and sticky header and footer, a summary ("N changed / M unchanged / K warnings"), a "changed only / warnings" filter, cards at 390px, Apply disabled until the preview is valid, and Cancel always available.
   - File input: use a wrapped field component, not a raw `<input type=file>`.
   - Order form (`order-form.tsx:55-63`, which seeds fee 0): stop-desk is disabled with an inline reason, the type auto-switches to home when the wilaya changes, and a `stop_shipping` wilaya shows a blocking message that is not colour-only. The same checks run server-side in `orders/actions.ts`.

9. **MEDIUM: brief:27, 33 (UI). The four states are undefined.** Define:
   - parsing (loading);
   - empty or invalid file;
   - oversize (more than 1 MB) or bad encoding;
   - apply in progress;
   - apply failed (the dialog stays open, the reason is shown, retry works);
   - success (toast plus the grid refreshes);
   - non-admin (no Upload button).

   Warnings get a type, a wilaya reference, an icon and text, not colour alone. Béchar's wording must be one the owner understands.

10. **MEDIUM: brief:28 (UI). The commune picker is unspecified.** `order-form.tsx:122` is a free-text `Input`.
    - Use the Combobox from `components/fields` and keep free text allowed.
    - Fall back to the plain input when a wilaya has no communes.
    - Clear the commune when the wilaya changes.
    - State which spelling is stored (ZR matches with `normalizeText`).
    - Isolate the text in RTL (`bdi` / `dir=auto`).

11. **LOW: `fees-section.tsx:118`.** `<Badge>🚫</Badge>` breaks the no-emoji rule. Replace it with a Lucide icon plus a label. The per-row Switches have no accessible name; name each by wilaya. The grid also needs a 390px layout and `tabular-nums`.
