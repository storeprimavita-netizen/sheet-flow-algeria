## Summary
Brief review (design, no code yet) by qa-reviewer, checked against D4/D34/D44/D45, migrations 00002/00004/00006/00022/00025/00030 and the local DB (rolled-back transactions).

## Findings (ranked)

### High
1. **Brief Step 4 / Files (reroute `product_stats`, `wilaya_stats`)**: `CREATE OR REPLACE VIEW` without a `with (...)` clause resets reloptions (verified locally on `customer_stats`). `product_stats` exposes sourcing cost, ad spend, expenses and is granted SELECT to `anon` and `authenticated`, so a replaced view runs as owner and leaks every workspace's cost data to the anon key. **Fix:** brief must mandate `with (security_invoker = true)` on every replaced view; add tests asserting view options and that anon/agent reads return 0 rows.
2. **Brief Definitions ("`exchange`/swap excluded") vs D44**: linked originals can change status later (14 local originals are `delivered`), so a `delivery_status not in ('exchange','swap')` filter counts them alongside their replacement. `swap_order` inserts the replacement as `confirmed` with `placed_at = now()`, inflating received/confirmation in the current cohort. **Fix:** exclude originals by `swapped_to_order_id is not null`; leave replacements out of received/confirmation but in delivery.
3. **Brief Done-when ("duplicates count as excluded")**: 2 of 3 local suspects are confirmed, one delivered. Rates drop them while `pnl_lines` revenue keeps them, so `cost_per_delivered`/`cpa_delivered` mix order sets; passing eligible ids only to the dashboard breaks the net-parity test at `src/lib/rls.test.ts:182`. **Fix:** one id set for `dashboard_stats`, `pnl_summary`, `pnl_by_product`; exclude a suspect only while unconfirmed; same set for money denominators.

### Medium
4. **Done-when on_road / test "on_road matches product_stock_stages.on_road"**: the view sums units (333 local orders qty > 1), includes replacements in `wait_for_deposit`, does not require confirmed (12 local unconfirmed on-road), ignores eligibility and dates. Parity test cannot pass. **Fix:** define on_road as `order_stock_target(...) < 0 and status <> 'delivered'`; return order and unit counts; run parity with null dates, on units, without eligibility.
5. **Definitions ("cancelled-after-pickup")**: undefined; 52 local delivery-`cancelled` orders have no ZR shipment. **Fix:** require a `zr_shipments` row or carrier-status history entry.
6. **Definitions (cohort Africa/Algiers)**: DB session is UTC and `pnl_lines`/`pnl_summary`/`dashboard_stats` use `placed_at::date`; Algiers-only in `kpi_lines` puts 23:00-24:00 UTC orders on different days per screen. **Fix:** one shared range predicate using `at time zone 'Africa/Algiers'` everywhere; test with an order at 23:30 UTC.
7. **Files (`kpi_lines(order_ids, from, to, product, filtered)`)**: finance/product pages call `pnl_summary` and have no id list; caller-supplied `filtered` and ids can contradict from/to. **Fix:** add `kpi_summary(from, to, product)` wrapper that selects orders itself.
8. **Files (consumers not listed)**: rerouting changes `stop_shipping_auto` (`src/app/app/settings/page.tsx:123`, dashboard losing-wilaya list) and the Real scenario in `src/lib/pricing-real.ts`; products/statistics pages absent. **Fix:** state the new stop-shipping rule and list these consumers.
9. **Definitions (matured)**: ambiguous phrasing. **Fix:** define per metric, relative to `now()`, with explicit numerator/denominator of the 20% share.
