## Findings (ranked)

### Medium
1. **Push lets orders through to unpriced wilayas.** `src/lib/integrations/zrexpress-push.ts:59-64`.
   - The guard only refuses when `order.delivery_fee == null`. Any order that already has a fee (manual, or a webhook payload with a fee) pushes into a `priced=false` wilaya, with only a `console.warn`.
   - This breaks D27: unpriced means shipping is off. The brief allows the keep-fee exception only for stop-desk orders in a wilaya that is now home-only.
   - Fix: refuse whenever `!feeRow.priced`. Warn and push only when `priced && !stopdesk_available && delivery_type='stopdesk' && delivery_fee != null`.
2. **Orders refused at push are stuck.** Same lines, plus `orders/actions.ts`.
   - Example: a webhook stop-desk order lands in a home-only wilaya. Its fee is left null, so push refuses it.
   - No action edits `delivery_type`/`delivery_fee` after creation, and the brief's "admin may override" is missing. The order can never ship.
   - Fix: add an admin-only "switch to home" action that re-seeds the fee via `deliveryFeeFor` (or an admin override flag on push).
3. **`swap_order` copies the old order's fee.** `supabase/migrations/00052_delivery_prices.sql:160`.
   - The new order B inserts `a.delivery_fee`. Example: a swap from Adrar (1400) to wilaya 16 pushes the wrong COD amount.
   - The brief lists swap as a consumer of the single fee source (D14). Here `delivery_fee_for` is only used as a guard.
   - Fix: insert `public.delivery_fee_for(a.workspace_id, p_wilaya_code, a.delivery_type::text)`. The guard above already ensures it is not null.
4. **Server-side order block throws instead of returning a form error.** `src/app/(app)/app/orders/actions.ts:379-386`.
   - A bypass (stale tab, or a fee flipping after page load) shows the framework error page with untranslated `Cannot create this order: type_unavailable`.
   - `swapOrder` lets the RPC exception propagate the same way.
   - Fix: return an `{error}` state with an i18n key, and show it inline.
5. **The fees grid is a nested scroll box on phones.** `src/app/(app)/app/settings/fees-section.tsx:49`.
   - `max-h-[28rem] overflow-auto` around cards at 390px gives a box about 2 cards tall, and the second card is cut off mid-row (`grid-en-dark-390.png`).
   - Fix: apply `md:max-h-[28rem] md:overflow-auto` only from `md:` up, and let the page scroll on mobile.
6. **Dialog preview values are forced LTR in AR.** `fees-csv-dialog.tsx`, `PreviewRow` `<dd dir="ltr" … text-start>`.
   - Values are pinned to the far left with a wide gap from the labels on the right. The `→` is not mirrored, and the Arabic "بلا سعر"/"المنزل فقط" sit inside an LTR run (`dialog-ar-light-1280-b.png`).
   - Fix: keep the page direction and wrap only the numbers in `<bdi dir="ltr">`.
7. **Blocking alert on the order form is far from its cause.** `src/app/(app)/app/orders/order-form.tsx:~180-198`.
   - The unpriced/stopped alert renders by Save, a screen away from Wilaya at 390px (`order-unpriced-en-dark-390.png`).
   - With block `type_unavailable`, Save is disabled and no reason is shown, because the hint is hidden when `block` is set.
   - Fix: put the alert under the Wilaya field (or mark it invalid), and always show a reason when Save is disabled.
8. **Screenshot set is incomplete.** `docs/design/audit/P1-7/` has 3 PNGs, all AR/light/1280.
   - The brief requires dark+light, EN+AR, 1280+390 for 6 dialog states (populated, warnings, changed-only, oversize/malformed, applying, failed), the grid, and the order form (stop-desk disabled, stop_shipping wilaya, commune picker open).

### Low
9. **`apply_delivery_prices` accepts some bad input** (`00052:67,72-74`). These only reach it through a direct admin RPC call.
   - A missing `wilayas` key passes, because `jsonb_typeof(null) <> 'array'` is NULL. Fix: `coalesce(...,'') <> 'array'`.
   - `NaN`/`Infinity` fees pass the `< 0` check. Fix: reject non-finite values.
   - `priced=true` with a null `home_fee` becomes 0 DZD. Fix: require non-null fees when the type is available.
10. **Re-enabling a wilaya can expose a 0 DZD fee.** New unpriced/home-only rows are stored with fee 0 (`00052:99-100`). Toggling Priced/Stop-desk on in the grid shows an empty `MoneyField` and posts 0, so the wilaya goes live at 0 DZD (`fees-section.tsx:99,119`).
    - Fix: require a fee > 0 before the toggle can save.
11. **The oversize message never appears.** The default server-action body limit (1 MB) rejects large uploads before zod runs, so the client shows the generic "invalid" text (`fees-csv-dialog.tsx:53`).
    - Fix: check `file.size` on the client before calling the action.
12. **File input is English in the AR UI.** `file-field.tsx` is the native input, so "Choose File / No file chosen" stays English, and the chosen filename is never shown because `onChange` clears the value.
    - Fix: use a custom label and show the file name.
13. **Unpriced wilayas missing from warnings.** The unpriced names list and `formatHint` in `fees-csv-dialog.tsx:~163-169` are not wrapped in `<bdi>`.
    - The 4 unpriced wilayas are not counted in the "Warnings" filter or count.
14. **Apply stays enabled with 0 changes.** The 390px footer stacks Apply and Cancel at about 160px tall. Fix: use a two-column footer.
15. **Commune Combobox labelling.** Options have no `bdi`/`dir=auto`, and `htmlFor="commune"` does not point at the Combobox trigger.
    - The Unit price and Delivery fee fields have no accessible name (may be pre-existing).
16. **CSV format hint is in the wrong place.** It appears only inside the dialog. The brief puts it under the Upload button. The grid also has no one-line purpose text.
17. **The snapshot `updated_at` checks are check-then-write.** In `saveWilayaFees`/`applyDeliveryCsv` the race window stays open. Acceptable for a single admin; note it.
