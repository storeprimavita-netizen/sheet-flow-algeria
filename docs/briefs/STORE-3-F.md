# STORE-3-F — Atomic selling saves and publish checks

risk: high · surface: ui,security · lane: store

Goal: save each selling configuration atomically, keep offer IDs stable, and refuse publishing products without a storefront price.

## Done when

- Pricing changes commit the mode, compare price, option deltas and variant overrides together. Per-value → uniform and per-value → per-variant clear every option delta. Leaving per-variant clears inactive override data. A failed save preserves the previous configuration.
- Quantity offers and the bump save together. Existing rows keep their IDs through edits, reordering and another save without reload. New quantity IDs return to the editor, intentional removals still work, and concurrent saves leave one coherent list with at most one default and bump. A failed save preserves the previous list.
- Pricing, offers and form actions refresh the public store tag after success. Selling shows an EN/AR hint when variant products have positive unassigned stock, matching D58 and counting stock on all variants.
- Publishing and replacing the product on a published page use the same `unit !== null` price criterion as the public product DAL. Admin editor readiness agrees with its action. Priced sold-out products remain publishable. Preserve the existing no-base and active-variant rules from the DAL.

## Steps and files

1. **Transactional database saves** — next migration after `00086_customer_score.sql`, currently `00087_selling_transactions.sql`. Add two bounded `security invoker` RPCs, one for pricing and one for offers. Set a fixed search path, check authenticated admin and current workspace in each body, use explicit workspace and product predicates, revoke default execute and grant only authenticated. Keep existing table RLS, composite FKs and audit triggers. Use the product transaction advisory lock already used by `save_variant_config` before checking/writing rows. No new table or table grants.
   - Validate JSON shape, counts, required values, ranges, unique IDs and product membership in the RPC contract. Reject stale or foreign existing IDs before applying. Use set-based scoped updates for prices, clearing deltas outside per-value and overrides outside per-variant. Raise on error so the entire write rolls back.
   - Save ordered quantity rows by existing ID or insert a new row, return IDs in input order, and update the existing bump by kind. Scope removals to the saved product and clear the old default before applying the new one. Keep the existing trigger validation for bump candidates. No order-history persistence or offer lifecycle changes beyond stable IDs for retained rows.
   - Document both RPC contracts and grants in `docs/DB.md`, reset locally and run `scripts/gen-types.sh`. Gate and push.
2. **Selling actions and editor** — `src/app/(app)/app/catalog/products/[id]/selling/actions.ts` keeps `requireAdminProfile`, Zod, session client and translated action errors, calls one RPC per save, then `invalidateStorePublic()` using `updateTag('store-public')`. Correct the moved Selling route in `revalidatePath`. Keep `saveForm` on the existing scoped write. In `_components/offers-editor.tsx`, reconcile returned IDs with the submitted client row keys without reverting in-flight edits or replacing row keys. Reuse existing `SaveBar` states. `selling/page.tsx` selects `stock` and adds a translated hint from stock minus all `loadProductVariants` stocks when the remainder is positive and variants exist. Add string to `src/messages/{en,ar}.json`. Gate and push.
3. **Publish guard** — extract the effective product price read/calculation inside `src/lib/store/data.ts` into a shared server-only helper, reusing `loadVariants`, `unitPrice` and `lowestPrice` so price mode, inactive rows and zero treatment agree. Keep preview DTO and public publication filters intact. `src/app/(app)/app/store/actions.ts` uses the helper in `assertPublishable` with the authenticated session client and workspace-scoped product read. Keep the checked product/status predicates on page mutations. `src/app/(app)/app/store/pages/[id]/page.tsx` calculates readiness only for the linked product and uses existing translated feedback. Gate and push.
