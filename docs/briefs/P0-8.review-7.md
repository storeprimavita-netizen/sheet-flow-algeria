   - Cause: the target function ignores `confirmation_status`, and the trigger does not fire when `confirmation_status` changes.
   - Repro (rolled back): A is delivered and swapped to B, then `update orders set confirmation_status='cancelled'` on B. Stock stays the same, B's target stays -qty, and the view shows on_road = 1.
   - Reachable: admins can take the confirmation-status path through `transition_order_status` (`src/app/app/orders/actions.ts:205`).
   - This contradicts "cancelled holds nothing" (D34). Normal orders are unaffected, because waiting for deposit already means a target of 0.
   - Fix: treat `confirmation_status='cancelled'` as not a replacement (target 0), and add `confirmation_status` to the trigger's column list.
