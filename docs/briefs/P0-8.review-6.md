## Findings (ranked)

1. **MEDIUM: an order inserted already linked does not reconcile its replacement.** `supabase/migrations/00028_stock_three_stages.sql:145`
   - Failure: the replacement reconcile only runs on UPDATE (`tg_op = 'UPDATE' and old.swapped_to_order_id is distinct from ...`). Reproduced as admin: B is `wait_for_deposit` with qty 1, then C is inserted with `swapped_to_order_id = B`. Result: `products.stock` stays 10, but the view shows on_road = 1. B counts as a replacement but has no movement.
   - This breaks the rule that the trigger and the view always agree, until B's status changes.
   - Fix: also reconcile `new.swapped_to_order_id` on INSERT when it is not null.

2. **MEDIUM: nothing limits who sets `swapped_to_order_id` or how many orders point at one replacement.** `00028_stock_three_stages.sql:120-124`, plus `guard_order_fields` (admins are unrestricted).
   - Failure: A2 is `in_transit` and holds 1 piece. A direct admin PATCH links A2 to an existing replacement B. Stock goes 8 -> 9 and on_road 2 -> 1 while the parcel is still with the carrier. The log says `order_swapped`, not a correction. Agents are blocked by the guard.
   - Fix (owner to confirm): allow link changes only inside `swap_order`, using a transaction-local setting checked in the trigger (the same pattern as `mnw.assign_self`), and/or add a unique partial index on `orders(swapped_to_order_id) where swapped_to_order_id is not null`.

3. **LOW (D41 as written; owner to decide): deleting an on-road replacement puts the piece back in the warehouse.** `00028_stock_three_stages.sql:172-173`
   - Failure: B is `in_transit` and A is `swap`. Deleting B gives +1 in stock, and A's target is 0, so nothing takes the piece back. This conflicts with D41's principle that pieces still with the carrier do not return.
   - Fix: release a replacement on delete only when it has not been picked up yet.

4. **LOW: misleading log when swapping a delivered order.** `00028_stock_three_stages.sql:302-304` with `:87-90`
   - Failure: A is set to `swap` before the link is written. That logs `+1 order_returned` on A, then `-1 order_swapped` on B, so the log says a piece came back when it never did.
   - Fix: link first, then change the status.

5. **LOW: a double submit can re-point the customer.** `src/app/app/orders/actions.ts:452-460`
   - Failure: on the second submit, `swap_order` returns the existing B, but the action still updates B's `customer_id` from that form. The update result is not checked, so a failure there is silent.
   - Fix: skip the customer update when B already existed, and check the error.

6. **LOW (existed before this branch): a product inserted with non-zero `stock` has no log row.** `products_stock_guard` covers UPDATE only.
   - Fix: on INSERT, require stock 0, or write a `correction` movement.
